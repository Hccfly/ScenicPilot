# 证据片段标注与 chunk 参数消融

## 1. 结论

当前珠海长隆语料的运行配置确定为：

```python
chunking_strategy = "heading-parent-child-v2"
child_size = 640
child_overlap = 128
parent_size = 960
answer_context_limit = 3
answer_context_token_budget = 2200
```

正式评测使用本地 `BAAI/bge-small-zh-v1.5`，不调用外部模型 API。30 条真实问题均
增加了一条人工核验的最小决定性官网原文片段；片段只忽略抽取过程中产生的空白差异，
不做语义模型裁判。

最终配置的核心结果：

| 指标 | 结果 |
| --- | ---: |
| Recall@5 | 1.000000 |
| MRR@10 | 0.816667 |
| nDCG@10 | 0.864674 |
| parent 证据完整度 | 1.000000 |
| child 直接证据命中率（诊断项） | 0.666667 |
| 平均上下文估算 tokens | 1388.90 |
| P95 上下文估算 tokens | 2057 |
| 去重前同 parent 重复率 | 0.482626 |
| 上下文预算耗尽用例 | 1 / 30 |
| 跨景区/demo/禁返来源泄漏 | 0 / 0 / 0 |

这里的 token 是固定 Unicode 估算器结果，用于同批配置横向比较，不是任一模型供应商的
计费 token。

## 2. 为什么先修改结构，再比较参数

V1 把每一个 Markdown 标题都当成 parent 边界。酒店、餐饮和表演聚合页因此产生了
`### 飞船餐厅`、`### 酒店介绍` 这类只有几字的 parent；正确来源虽然排在第一，回答
入口拿到的却只有标题，修改 `parent_size` 不会让这些 parent 变长。

在 V1 的 320/48/1600 基线上：

- Recall@5 = 1.0；
- MRR@10 = 0.811111；
- parent 证据完整度只有 0.8；
- 失败集中在 6 个聚合/概览问题。

V2 保留叶子标题作为 child 锚点，但 parent 改为在文档或 H1/H2 子树中按预算打包。
这使小 child 负责定位、parent 负责提供完整上下文，且让 `parent_size` 真正成为可评测
参数。V1 实现仍保留，用于历史索引兼容和对照。

## 3. 标注契约

`data/eval/retrieval_cases.jsonl` 每条样本增加：

```json
{
  "gold_evidence_spans": [
    {
      "source_id": "ocean-whale-shark",
      "text": "除了有世界上至大的鱼类之一的鲸鲨，更有直径达4米长的魔鬼鱼。",
      "label": "核心展示动物"
    }
  ]
}
```

当前每个问题标注一条“足以证明检索命中正确内容”的最小片段，适合比较 chunk 参数；
它不等价于多事实问题的完整答案清单。离线评测阶段 端到端评测应继续补充原子事实覆盖率和最终
回答忠实度。

## 4. 两阶段消融

第一阶段固定 `parent=1600`，比较 15 组 child/overlap：

```text
child = 160, overlap = 0 / 24 / 32
child = 240, overlap = 24 / 32 / 48
child = 320, overlap = 32 / 48 / 64
child = 480, overlap = 48 / 64 / 96
child = 640, overlap = 64 / 96 / 128
```

shortlist 同时保留质量、直接证据和效率代表，避免用单一加权分数把候选压向一个尺寸
极端。第二阶段对代表配置比较：

```text
parent = 640 / 960 / 1200 / 1600 / 2400
```

硬门槛为 Recall@5 ≥ 0.95、MRR@10 ≥ 0.80、parent 证据完整度 = 1.0、上下文预算
耗尽用例不超过 1 条，且所有泄漏指标为 0。在平均上下文 token 最低值 5% 以内，再按
去重前重复率、索引字符量和 MRR 决定。

`child_evidence_recall` 只作诊断，不作硬门槛。原因是 parent-child 检索允许 child
命中实体标题，再由对应 parent 提供证据；把完整证据必须直接落在 child 设为门槛，会
错误否定这套设计。

## 5. 关键对比

| 配置 | Recall@5 | MRR@10 | 证据完整度 | 平均 tokens | 重复率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 160/0/960 | 1.000 | 0.850 | 1.000 | 1428.97 | 0.560 |
| 240/48/960 | 1.000 | 0.820 | 1.000 | 1445.37 | 0.550 |
| 480/48/960 | 1.000 | 0.817 | 1.000 | 1343.27 | 0.504 |
| **640/128/960** | **1.000** | **0.817** | **1.000** | **1388.90** | **0.483** |
| 480/48/640 | 1.000 | 0.810 | 0.967 | 1043.67 | 0.470 |
| 640/128/640 | 1.000 | 0.790 | 0.967 | 1020.43 | 0.440 |

`parent=640` 成本最低，但证据完整度只有 29/30；960 是首个达到 30/30 证据覆盖的
parent 档。480/48/960 的平均 token 最低，640/128/960 仍在 5% 成本带内，MRR
相同，同时将实际索引 child 从 319 减至 309、重复率从 0.504 降至 0.483，因此作为
平衡配置。128 字 overlap 是 child 大小的 20%，用于降低跨句边界断裂。

160 字 child 的 MRR 更高，但重复率和索引规模明显增加；当前 30 条问题不足以证明这点
排序收益能覆盖长期索引与候选多样性成本，保留为质量敏感备选，不作为默认值。

## 6. 索引准入与上下文预算

最初 21 个详情页中的卡片标题，以及酒店概览中的 `## 评分：` 等标题行，会形成没有
正文的 child/parent。它们的页面质量分很高，却可能占满同 source 最多两个 parent 的
回答槽位。最终准入规则是：

- child 有实质正文时索引；
- child 只有标题、但对应 parent 有正文时仍索引，用作实体路由；
- child 和 parent 都只有标题时不进入 BM25/向量索引。

在最终配置下共生成 397 个 child，其中 88 个无实质内容块被排除，309 个进入正式
索引；174 个 parent 只用于回填。该规则修复了 `ret-025`“迎海酒店公寓适合住宿吗”
被标题块占位的问题。

回答上下文另做了固定 `limit=3` 的预算消融：1200、1600、2000、2200、2400、2800。
2200 是首个满足 30/30 证据完整、泄漏为 0 且预算耗尽率不超过 5% 的预算，因此作为
默认值。选择器同时对“预算耗尽用例数”设硬门槛，防止较大 parent 因大量候选被预算
跳过而显示出虚假的低平均 token。

| token 预算 | 证据完整度 | 平均估算 tokens | 预算耗尽用例 |
| ---: | ---: | ---: | ---: |
| 1200 | 1.000 | 1019.6 | 17 |
| 1600 | 1.000 | 1209.6 | 10 |
| 2000 | 1.000 | 1335.5 | 4 |
| **2200** | **1.000** | **1388.9** | **1** |
| 2400 | 1.000 | 1410.5 | 0 |
| 2800 | 1.000 | 1410.5 | 0 |
